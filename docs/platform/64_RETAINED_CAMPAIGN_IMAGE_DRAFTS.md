## Sharing, ownership and retention

New images can be copied into a draft only from the saving owner's own active, accepted creator/site/workspace inventory. The owner explicitly confirms both image/text/rights review and **sharing these selected images and their rights with current site members**. This is private workspace sharing, not publication. Other inventory items remain creator-private. A viewer/editor can load the shared draft, inspect its targets/history and download its selected images, but cannot use owner composition/save controls. Server and SQL authorization remain authoritative.

The copied artifact stores immutable descriptor, original accepted review, creator identity and a private server-only object path. The already-sanitized physical object is immutable and reference-retained; it is not duplicated in Storage or represented by a mutable/public/signed creator URL. The image artifact has no creator/library FK, so library archive/deletion cannot rewrite or remove it. New owners may reuse this generation's previously shared artifact; they cannot use this mechanism to inspect another creator's unrelated library or another generation/site.

Historical references remain retained even after the latest image draft removes a target. The draft snapshots the entire base visual, including its private-template provenance, so later text/template changes do not rewrite earlier image exports. Site/generation deletion cascades retained references; operator cleanup can then remove known unreferenced objects if no original private-library reference remains. Both creator and global claim/finish functions protect retained paths. No cleanup, hosted deletion or permanent account deletion was executed.

Existing source-review account FKs can independently block permanent creator deletion. This delivery neither changes those FKs nor adds an account-deletion workflow. The isolated SQL fixture removes its own restrictive review row before testing account-cascade retention, specifically to test this artifact boundary; it is not an instruction to delete production reviews. Snapshot actor nulling is allowed only for a deleted actor and otherwise-identical immutable revision, preserving existing FK teardown behavior.

## Atomic save and byte boundaries

The separate `campaign-media-working-copy-v1` wrapper becomes the persisted image-draft payload. Existing base campaign visual saves continue accepting v1/v2/v3 only. The owner first saves/reviews the base text/layout visual; image save then requires an exact matching base version/document/source review. Generation success, approved QA without blockers and latest accepted human review are rechecked inside SQL. Expected image version guards conflicts; an unchanged reviewed save returns the same version. Up to50 immutable image revisions are supported.

Strict payload validation caps48 KiB, nine unique targets and three distinct media ID/version pairs; numeric fields, descriptors and reference hashes are checked. Client descriptors must exactly equal authoritative accepted upload metadata or an already-retained artifact. Fresh artifacts require a registered committed immutable upload, locking its attempt against cleanup. Descriptor/rights/path provenance cannot be rewritten by ordinary image saves. No caller-supplied object path is accepted.

Site-level advisory admission serializes shared retained-byte quota across generation results. At most160 MiB of distinct retained object paths/site is allowed, including history; repeated references to the same physical path do not multiply its byte count. New artifact insertion, quota checks, current draft and history writes occur in one transaction. A quota/validation/conflict failure leaves no new retained row or draft version. Original creator-library quotas remain separate and unchanged.

Before save, the server verifies actual selected object bytes, sizes and SHA-256, using only creator-private or already-shared generation-specific access. A503 setup/integrity error is not bypassed by falling back to another path. GET byte reads recheck current membership, resolve the generation/site/media/version through a service-only RPC, verify the exact original-creator path plus size/hash, and return only authenticated raster bytes with private/no-store and nosniff. Browser-facing JSON contains no Storage path or credential. Already obtained downloads cannot be retracted.

## Interface and compatibility

Open accepted campaign → Visual drafts → **Reviewed images — saved drafts and private exports**. Opening the panel loads the latest image draft. The owner can load accepted inventory, assign targets, remove targets, select current text/layout, review/share and save. Saved image history previews its own immutable text/layout and images. Viewing a history entry does not replace the latest saved pointer. A renewed source review requires renewed image review; historical source mismatches block member export until the owner reviews/resaves appropriately.

Unsaved local exports remain available after explicit review. Labels and filenames distinguish saved versus unsaved working copies. Save failures keep local edits; reload/history navigation confirms discarding dirty edits. Only dirty owner drafts trigger unsaved navigation/sign-out warnings; a clean saved draft survives refresh.
