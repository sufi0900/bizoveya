Only the plan's exact selected agent identities/versions enter the snapshot; unrelated globally qualified agents do not. Preparation requires current checked preview/latest agents, enabled role binding, matching checked model/credential versions, successful current-adapter connectivity evidence within24 hours and enabled valid reviewed pricing. Saved output limits must fit both agent and model limits. Approved site knowledge is required and only approved fact references/text are captured; raw source documents are excluded. Site preferences, exact binding/profile/credential/connectivity/pricing versions and ordered turn purposes are pinned privately.

The browser receives approved facts/preferences, pinned role/version identifiers, pricing expiry, token bounds and cost estimates. It never receives credential values/references, private agent instructions, full model documents or the private runtime snapshot. A SHA-256 fingerprint covers the entire private execution input. Save recomputes qualification and that fingerprint transactionally; changes to context, preferences, bindings, pricing or plan/schedule prevent an unreviewed save.

It must fit the saved total meeting ceiling, each per-request model ceiling and aggregate per-profile daily/model ceiling. Unknown/overrun accounting and expired reservations in the existing connectivity/generation ledgers block preparation. **This does not reserve money, subtract today's prior spend, establish current affordability or authorize a provider call.** Shared daily spending, actual prompt-token admission, current adapter capability, lease/authorization and current dependency rechecks must be enforced independently at future reservation/provider-start boundaries. ## Persistence and retries

The owner reviews the displayed current candidate and checks `I reviewed this approved context, pinned turns and exact limits. Save the snapshot only.` Confirmation is tied to its fingerprint and exact parent/schedule identities. Shared synchronous action locking prevents room refresh/scheduling/preparation overlap. The same exact in-memory attempt retains its snapshot UUID after a failed/lost response; exact SQL retry returns the recorded prepared truth without duplicating or granting execution, even after pause or qualification expiry. Changed commands/identities conflict; revoked membership denies even a retry. Refresh projects the immutable saved summary to workspace members read-only. No pause, cancel, review or reload overwrites the snapshot. A changed snapshot is never silently substituted; future stale preparation needs an explicitly reviewed fresh workflow.

The full private input and sanitized summary are immutable, one row per plan, cascading with site deletion. Saving does not advance parent/schedule versions or append a false execution event; snapshot actor/time/id form the preparation provenance. The existing schedule's pause/cancel controls remain available. Prepared never means running.
